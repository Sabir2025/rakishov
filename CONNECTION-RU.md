# Связь двух сайтов

Публичный сайт и аналитика размещаются на разных хостингах, но подключаются к ОДНОМУ проекту Supabase. Публичная форма отправляет заявку в функцию `intake`. Функция сохраняет её в общей таблице `leads`. Кабинет после входа владельца читает ту же таблицу через защищённый API. Обмен файлами между хостингами не нужен.

## Если база уже подключена

Не создавайте новый проект Supabase, не удаляйте таблицы и не запускайте заново начальные миграции. Перенесите действующие публичные настройки в оба новых проекта. Существующие заявки останутся в той же базе.

## Настройки обоих сайтов

В КАЖДОМ архиве откройте `js/settings.js` и укажите одинаковые значения:

```js
supabaseUrl: 'https://ВАШ_PROJECT_REF.supabase.co',
supabasePublishableKey: 'ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ',
```

В публичном сайте дополнительно укажите `turnstileSiteKey`. В аналитике он не нужен. Пароль владельца, секрет Turnstile и service-role key в эти файлы не добавляются.

После изменения настроек выполните `python3 scripts/package_site.py` в каждом проекте: он перенесёт настройки в `dist/`. Если нет Python и вы используете готовые папки, одинаково отредактируйте `js/settings.js` и `dist/js/settings.js` в соответствующем проекте.

## Домены

- Разместите содержимое `rakishov-public/dist/` на основном хостинге.
- Разместите содержимое `rakishov-analytics/dist/` на отдельном хостинге. Кабинет открывается в корне его адреса, список заявок — `/leads/`.
- В секрете Supabase-функции `intake` под названием `ALLOWED_ORIGINS` укажите точный origin публичного сайта: например `https://portfolio.example.com`, без пути и конечного `/`. При сохранении старого сайта перечислите оба адреса через запятую. Не используйте `*`.
- Разрешите домен публичного сайта в настройках Turnstile. Домен аналитики Turnstile не использует.
- В Supabase Authentication → URL Configuration укажите адрес аналитики как Site URL для связанных с входом почтовых переходов. Сам вход по паролю выполняется напрямую через Supabase Auth.
- Аналитика не вызывает `intake`; она использует Supabase Auth и REST API с токеном владельца. Не нужно разрешать публичному сайту читать HTML или данные хостинга аналитики.

## Если Supabase ещё не создан

SQL, функция и инструкция первоначальной настройки находятся в архиве аналитики. Подключение выполняется один раз для обоих сайтов. В выданных архивах URL и ключи пока пустые: реальные аккаунты и хостинги не подключались.

## Проверка после размещения

1. Отправьте одну тестовую заявку через публичный сайт и пройдите Turnstile.
2. Убедитесь, что форма показала ID сохранённой заявки.
3. Откройте другой домен с аналитикой, войдите и нажмите «Обновить».
4. Найдите заявку в списке, измените статус и проверьте историю.
5. Выйдите из кабинета: данные должны быть недоступны без авторизации.

Заявки сохраняются независимо от того, открыт кабинет или закрыт. Кнопка «Обновить» или повторный вход загружает свежие данные. События посещений собираются после согласия посетителя; сохранение заявки от согласия на статистику не зависит. Ссылки «Кабинет владельца» и «Настройки статистики» из публичного подвала удалены, но первоначальный запрос согласия на статистику сохранён.

## Защита данных

Отдельный домен сам по себе не защищает данные. Защита обеспечивается Supabase Auth, RLS и записью UUID владельца в `profiles`. Публичная форма не имеет доступа к чтению заявок. Не открывайте доступ к таблицам для `anon` и не размещайте серверные секреты в публичных папках.

Локально проверена связка адресов API с тестовыми HTTP-ответами. Сквозную работу на двух живых хостингах нужно проверить после настройки; подключение к пользовательским аккаунтам не выполнялось.
